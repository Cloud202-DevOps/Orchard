Executive Summary

Repository Status: 🟠 Remediation Required

Key Findings: Orchard CMS is a legacy ASP.NET MVC 5 monolith on .NET Framework 4.8 with no cloud infrastructure, no IaC, no containers, and self-managed SQL Server databases. The application has strong modular architecture (62 modules with defined interfaces) but shares a single database and deployment unit. CI exists (GitHub Actions) but no deployment automation.

Remediation Plan: Phase 1 focuses on foundational infrastructure (IaC, managed database, secrets management, network security). Phase 2 addresses containerization, .NET modernization, and observability. Phase 3 tackles decomposition and advanced operational practices.

Recommended Actions:

  1. Implement IaC (AWS CDK with C#) for all infrastructure and establish CI/CD deployment pipeline
  2. Migrate database to Amazon RDS for SQL Server and secrets to AWS Secrets Manager
  3. Containerize the application (Windows containers on ECS Fargate) as a stepping stone to decomposition

Detailed Findings

HIGH INF-Q1: Managed Compute

Category: Infrastructure & DevOps
Finding
No managed compute infrastructure found. The application is deployed via MSDeploy to traditional IIS on Windows Server. No ECS, EKS, Lambda, or Fargate resources defined.
Recommendation
Containerize the application using Windows containers on ECS Fargate. Long-term, migrate to .NET 8+ for Linux containers and serverless options.

HIGH INF-Q2: Managed Databases

Category: Infrastructure & DevOps
Finding
SQL Server and SQL CE as database providers via NHibernate. No managed database infrastructure (RDS, Aurora) defined.
Recommendation
Migrate to Amazon RDS for SQL Server (minimal code change) or Aurora PostgreSQL (leveraging existing PostgreSQL dialect).

HIGH INF-Q5: Network Security

Category: Infrastructure & DevOps
Finding
No VPC, subnet, security group, or network segmentation configuration found.
Recommendation
Define VPC with public/private subnet tiers, least-privilege security groups, and deploy in private subnets behind an ALB.

HIGH INF-Q10: Infrastructure as Code Coverage

Category: Infrastructure & DevOps
Finding
No IaC found. No Terraform, CloudFormation, CDK, or Helm. All infrastructure is manually provisioned.
Recommendation
Adopt AWS CDK (C# supported, aligning with team skills) or Terraform to define all infrastructure.

HIGH SEC-Q5: Secrets Management

Category: Security Baseline
Finding
Connection strings in Web.config with no Secrets Manager, Vault, or encrypted parameter store. No rotation mechanism.
Recommendation
Migrate all secrets to AWS Secrets Manager with automated rotation. Remove plaintext credentials from configuration files.

HIGH DATA-Q1: Unstructured Data Storage

Category: Data Platform
Finding
Unstructured data stored via FileSystemStorageProvider on local disk. No S3 or cloud storage configured.
Recommendation
Migrate media storage to Amazon S3. Implement S3-backed IStorageProvider. Add CloudFront for delivery.

MEDIUM INF-Q11: CI/CD Automation

Category: Infrastructure & DevOps
Finding
GitHub Actions CI pipelines exist for compilation and testing. No deployment automation — no CD pipeline deploys to any environment.
Recommendation
Extend pipeline to include deployment stages using CDK deploy or CodeDeploy with environment promotion.

MEDIUM APP-Q1: Programming Languages

Category: Application Architecture
Finding
C# 7.3 targeting .NET Framework 4.8 with ASP.NET MVC 5.3. Legacy platform — not .NET Core/.NET 6+.
Recommendation
Migrate to .NET 8+ with ASP.NET Core for modern cloud-native support, Linux containers, and AWS SDK v3.

MEDIUM APP-Q2: Monolith vs Microservices

Category: Application Architecture
Finding
Single deployable unit with 62 modules sharing a single NHibernate session and database schema.
Recommendation
Enforce module boundaries, separate schemas per module, then apply Strangler Fig for extraction.

MEDIUM OPS-Q6: Integration Testing

Category: Operations & Observability
Finding
SpecFlow BDD tests exist (29 features) and run in CI, but test in-process — not against deployed services.
Recommendation
Add integration tests with real SQL Server (TestContainers). Add contract tests when decomposing.

LOW APP-Q5: API Versioning Strategy

Category: Application Architecture
Finding
No explicit API versioning strategy. Web API routes do not include version prefixes.
Recommendation
Adopt URL-path versioning (e.g., /api/v1/) when modernizing the API layer.

LOW SEC-Q7: Application Security Pipeline

Category: Security Baseline
Finding
Code analysis rulesets exist and are integrated into build. No dedicated SAST tool or dependency scanning in CI/CD.
Recommendation
Add Dependabot for NuGet dependency scanning. Integrate SonarQube or Semgrep SAST.
